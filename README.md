# กล่องบรีฟ (BriefBox)

แอป Mac ที่เขียนให้แฟนใช้ เพราะเขาทำงานกราฟิกและวิดีโอ แล้วได้บรีฟงานทางอีเมลวันละหลายฉบับ
ลากอีเมลมาวาง แอปจะแยกชิ้นงาน ขนาด และวันส่งให้ จากนั้นเตือนผ่านแอป Reminders ซึ่งเด้งไปถึง iPhone ด้วย

> ⚠️ เวอร์ชันทดลอง (v0.1) ตั้งใจทำให้คนคนเดียวใช้ ไม่ใช่แอปสำเร็จรูป ไม่มีตัวติดตั้งและไม่มีอัปเดตอัตโนมัติ
> ใช้แล้วข้อมูลหายหรือแอปทำงานผิด ผู้เขียนไม่รับผิดชอบ (ดู [LICENSE](LICENSE))

## ทำอะไรได้
- ลากไฟล์ `.eml` มาวาง (จาก Outlook หรือ Mail) แอปจะแยกชิ้นงาน ขนาด และวันส่ง ตรงไหนไม่แน่ใจจะตั้งเป็นคำถามไว้
- ทุกงานต้องผ่านหน้า **รอตรวจ** ก่อนเข้ารายการจริง แอปไม่เพิ่มงานเองโดยไม่มีคนดู
- เพิ่มงานเองได้ สำหรับงานที่สั่งปากเปล่าหรือสั่งทาง LINE (⌘N)
- หน้าวันนี้เรียงงานตามวันส่ง และมีปฏิทินรายเดือน
- สร้างโฟลเดอร์งานและตั้งชื่อไฟล์ส่งออกให้ (`{งาน}_A{n}_{ขนาด}`)
- อีเมลตอบกลับที่สั่งแก้ จะถูกบันทึกเป็นรายการแก้
- ไอคอนบน Dock ขึ้นตัวเลขจำนวนงานที่ถึงกำหนดหรือรอตรวจ
- สำรองข้อมูลวันละครั้ง เก็บย้อนหลัง 7 วัน

## ความเป็นส่วนตัว
- ไม่มีเซิร์ฟเวอร์ ไม่มี analytics อีเมลไม่ออกนอกเครื่อง
- AI ใช้ Apple Foundation Models ที่รันในเครื่อง ไม่ได้เรียก API ภายนอก
- แอปไม่ส่ง ไม่ร่าง และไม่ตอบอีเมลแทน
- ข้อมูลเก็บที่ `~/Library/Application Support/BriefBox/`

## ต้องมีอะไรบ้าง
- Mac ชิป Apple Silicon และ **macOS 26 ขึ้นไป**
- Xcode 26 ขึ้นไป หรือ Command Line Tools ที่มี macOS 26 SDK (ต้องใช้ FoundationModels)
- ถ้าจะใช้ส่วน AI ต้องเปิด Apple Intelligence ไว้ (ถ้าไม่เปิด แอปจะใช้กฎแยกอย่างเดียว)

## ข้อจำกัดที่ควรรู้
- ตัวแยกแบบกฎเขียนตามฟอร์มบรีฟของที่ทำงานแฟน ซึ่งขึ้นต้นหัวเรื่องว่า `MARCOM BRIEF:`
  - อีเมลรูปแบบอื่นจะส่งให้ AI อ่าน ซึ่งเพิ่งทดสอบกับอีเมลสังเคราะห์แค่ 5 ฉบับ
  - ถ้าฟอร์มของคุณไม่เหมือนกัน แนะนำให้แก้ `Sources/BriefCore/BriefParser.swift` (มี test ใน `Tests/`)
- Apple Foundation Models ยังไม่รองรับภาษาไทย อีเมลภาษาไทยจึงใช้กฎแยกแทน
- รองรับการลากไฟล์ `.eml` เท่านั้น ยังไม่ได้ต่อกับบัญชีอีเมลโดยตรง

## วิธี build
```sh
git clone https://github.com/tle-pratchaya/brief-box.git
cd brief-box
swift test
scripts/build-app.sh          # ได้ dist/BriefBox.app
open dist/BriefBox.app
```
แอปเซ็นแบบ ad-hoc บนเครื่องที่ build เอง จึงเปิดได้ทันที
ถ้าต้องการย้ายไปไว้ใน `/Applications` ให้ copy ด้วยคำสั่ง `cp -R dist/BriefBox.app /Applications/`

แนะนำให้ build เองแทนการส่งไฟล์ `.app` ให้กัน เพราะแอปไม่ได้ notarize
ถ้าเครื่องปลายทางเปิดไม่ได้ ไม่ควรแก้ด้วยการปิด Gatekeeper

## โครงโค้ด
- `Sources/BriefCore/`: ตัวอ่าน `.eml` (`MIMEMessage`), ตัวแยกแบบกฎ (`BriefParser`), ตัวรวมผล AI (`AIMerge`) และชื่อไฟล์ส่งออก ส่วนนี้ไม่มี UI จึงทดสอบได้ตรงๆ
- `Sources/BriefBox/`: แอป SwiftUI + SwiftData + EventKit
- `proto/parse_brief.py`: ต้นแบบ parser ตัวแรก เขียนด้วย Python
- `design/`: ไฟล์ออกแบบหน้าจอและไอคอนแมว

## ส่วนที่มีไว้ดูแลระยะไกลบนเครื่องของแฟน
ไม่ต้องใช้ แต่ควรรู้ว่ามีอยู่:
- `/Users/Shared/BriefBox/health.txt` และ `ai-status.txt` บอกเวอร์ชัน สถานะสำรองข้อมูล และสถานะ AI
- ถ้ามีไฟล์ `.eml` ใน `/Users/Shared/BriefBox-ai-test/` แอปจะให้ AI อ่านแล้วเขียนผลเป็น `.result.txt` ไว้ข้างไฟล์ ใช้ทดสอบ AI โดยไม่แตะฐานข้อมูล
- เมื่อไฟล์แอปใน `/Applications` ถูกเขียนทับด้วยเวอร์ชันใหม่ แอปจะเปิดตัวเองใหม่ แต่จะทำตอนที่ไม่มีคนใช้นาน ≥ 2 นาทีเท่านั้น
